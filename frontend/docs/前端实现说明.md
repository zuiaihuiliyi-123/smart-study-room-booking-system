# 前端实现说明（可追溯交付物）

> 适用范围：`frontend/` 当前实现（Vue 3 `<script setup>` + TS + Vite + Element Plus + Pinia + Vue Router + Axios + ECharts）。
> 需求基线：`docs/智慧自习室预约与管理系统-需求规格说明书（课程结构版）.md`（V2.0 定稿）。
> 撰写口径：**只写实际做到的部分**；未实现、依赖后端、按 mock 模拟而**不能**作为业务验证结论的内容，全部在 §4 / §5 如实标注。
> 生成方式：本文件的表项均从代码反向核对（`src/router/index.ts`、`src/api/*.ts`、`src/types/index.ts`、各页面与其 `use*.ts`），不是凭记忆填写。
>
> **界面文案约定**：需求编号（`FR-xxx` / `BR-xxx` / `ST-xxx` / 判定项 `C1～C6` 等）**只用于本文件与源码注释**做可追溯，
> **不在界面上出现**。页面上的提示一律用业务语言描述（例如「限制期满后系统会自动解除账户限制」而不是「按 BR-010 自动解除」）。
> 因此本文件里的编号是给评审对照用的，截图里看不到它们属于预期。

### 3.3 Element Plus 主题覆盖方式

1. **变量覆盖**：`index.scss` 第 2 节在 `:root` 上重写 `--el-color-primary` 及 `light-3/5/7/8/9`、`dark-2`（按「N×10% 白 + 余量本色」计算），并把 `--el-border-radius-base`、`--el-font-size-base`、`--el-card-border-radius` 指向 `--ssr-*`。
2. **组件级微调**：只针对必要之处写 `.el-table`、`.el-pagination`、`.el-drawer`、`.el-menu-item` 等选择器（见第 3、7、8 节），不引入第三方主题包。
3. **图标按需引入**：图标从 `@element-plus/icons-vue` 逐组件 import，不全局注册。
4. **响应式收口**（第 8 节）：`.el-drawer { max-width: 92vw }`、`.table-wrap` 横向滚动、`≤768px` 时筛选区纵向堆叠、`.page` 内边距降档。

## 5. mock 与真实后端的差异说明

> **核心声明：mock 通过 ≠ 业务验证通过。** 前端在 `VITE_USE_MOCK=true` 下用 MSW 在浏览器里模拟后端，凡是"验证通过"的结论，**只对界面与交互成立**，不构成对后端业务规则的验证。

### 5.1 相同点

- 路径、请求体字段、响应结构、分页结构（`{items,total,page,page_size}`）与 `src/api/*.ts` 的声明保持一致，切 `VITE_USE_MOCK=false` **不改业务代码**。
- 时间字段统一 `YYYY-MM-DDTHH:mm:ss`；时段 `[s, e)` 左闭右开、30 分钟粒度。
- 权限：管理端接口在 mock 里同样校验 `requireAdmin`（学生调用返回 403 `无权限执行该操作`）。

### 5.2 不同点（必须知道）

| 方面 | mock 行为 | 真实后端 |
|---|---|---|
| 数据存储 | 内存 DB，**整页刷新即重置为种子数据** | 持久化（PostgreSQL） |
| 并发冲突（FR-014） | 用 `armed_conflicts` 计数**模拟**下一次创建返回 409，不是真实并发控制 | 由数据库唯一约束/事务保证 |
| 幂等（FR-015） | 未真正实现幂等键，重复提交靠前端禁用按钮 | 需后端幂等键或唯一索引 |
| 违约判定（FR-022） | 没有定时扫描任务，种子数据直接给出违约记录 | 由后端扫描任务生成（周期 ≤1 分钟） |
| 黑名单到期自动解除（BR-010） | **无调度器**，"到期自动解除"只体现为「解除时若仍有手动限制则不恢复为正常」 | 需后端定时任务 |
| 时间 | mock 有 `serverNow()` 偏移机制，便于演示"过了 30 分钟" | 服务器时间 |
| 审计日志（NFR-009） | 只把 `reason` 收进请求体并弹「将记入审计日志」提示，**不落库** | 需写入 `audit_logs` |
| 脱敏（NFR-006） | mock 返回**未脱敏**的原值，掩码在**前端完成** | 建议后端同样脱敏，前端掩码作为兜底 |
| 失败注入 | 提供 XHR 错误注入用于验证失败态；参数非法返回 400 | 真实错误码与文案需后端对齐 |

### 5.3 验证归属

- 本仓库此前完成的**原型走查 PV-01～PV-07**（`index.html` v1.0）结论**仅覆盖界面层**（版式、信息密度、可点击路径），不代表需求已通过业务验收。
- 各轮"浏览器实测"均在 MSW 下完成，覆盖的是：界面渲染、交互流程、错误/空/加载三态、无障碍与响应式表现。
- **未经真实后端验证**的部分：并发冲突、幂等、自动违约判定、黑名单自动解除、审计落库、统计口径的最终数值。
