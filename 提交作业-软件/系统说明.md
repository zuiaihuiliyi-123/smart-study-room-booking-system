## 2 系统架构与目录结构
### 2.1 分层与调用方向
```text
前端 views → api（Axios）→ /api/v1 → 后端 api/v1 → services → models（SQLAlchemy）
                                              ↘ schemas（Pydantic 校验/序列化）
```
后端**没有**独立的 `repositories/` 与 `db/` 目录：数据库引擎与会话在 `app/core/database.py`，业务查询与事务在 `app/services/*`，路由层只做参数绑定、鉴权和响应声明。
### 2.2 后端实际目录树（`backend/`）
```text
backend/
├── app/
│   ├── main.py                 # FastAPI 实例、CORS、异常注册、/health、启停调度器
│   ├── api/router.py           # 汇总挂载 13 个 /api/v1 子路由
│   ├── api/v1/                 # auth users rooms seats reservations attendance violations
│   │                           # reviews complaints blacklist audit dashboard messages
│   ├── core/                   # config database dependencies exceptions security
│   ├── models/                 # 14 个 ORM 模型类 + enums.py（表名见第 7 节）
│   ├── schemas/                # 12 个业务模块的 Pydantic 模型 + common.py
│   ├── services/               # 15 个业务服务（预约、可用性、签到、违约、黑名单、看板等）
│   ├── tasks/                  # scheduler + auto_violation/auto_end_reservation/
│   │                           # blacklist_expiry/complaint_auto_close
│   └── utils/                  # time_utils、pagination、masking（PII 脱敏）
├── alembic/                    # env.py + versions/（10 个 revision 文件）
├── scripts/                    # bootstrap_db.py、init_db.sql、seed.py、seed_demo.py
├── tests/                      # 18 个测试模块 + conftest.py（SQLite 内存库）
├── alembic.ini / pytest.ini / requirements.txt / .env.example
└── start.bat                   # 仅启动后端，不建库、不迁移
```
### 2.3 后端各层职责

| 目录 | 职责 |
|---|---|
| `app/main.py` | 注册 CORS、统一异常处理器与 `/api/v1` 路由；lifespan 启停 APScheduler |
| `app/api/v1/` | 声明方法、路径、请求/响应模型与权限依赖（`get_current_user`、`require_admin`、`require_student`、`require_booking_user`），不写业务规则 |
| `app/services/` | 业务规则与事务边界：预约冲突/幂等、可用性校验、签到窗口、违约与黑名单、场地关闭、看板统计 |
| `app/models/`、`app/schemas/` | SQLAlchemy 2.0 声明式模型（约束/索引/外键）；Pydantic 2 校验与序列化、分页 `PageResult` |
| `app/core/` | `Settings`（`.env`）、数据库引擎与会话、JWT 签发/校验、权限依赖、`BusinessError` 统一错误 |
| `app/tasks/`、`app/utils/` | 定时任务（逐条独立事务、幂等）；时间区间/窗口、取消时限、分页、脱敏纯函数 |

│   ├── mocks/                   # MSW：browser/db/handlers/*（仅 mock 演示）

### 2.5 前端各层职责

| 目录 | 职责 |
|---|---|
| `api/` | Axios 统一附加 `Authorization: Bearer`、处理 401/403/业务错误；按后端模块拆分接口函数 |
| `views/` | 页面编排（学生端、管理端、登录/注册、404），具备加载、空数据、失败三种状态 |
| `components/`、`layouts/` | 座位图与筛选、预约表格/评价弹窗、投诉表单、管理端抽屉与冲突清单；两套壳层与侧栏菜单（系统管理员为空菜单） |
| `router/`、`stores/` | `beforeEach` 校验登录态与 `meta.roles`；Pinia 保存 token（`localStorage: ssr_token`）、用户与未读数 |
| `types/`、`utils/`、`mocks/` | 字段类型、组合式函数与格式化/脱敏、MSW 内存数据与 handlers |
### 2.6 前后端契约
- 业务接口前缀 `/api/v1`；开发期 Vite 把 `/api` 代理到 `http://127.0.0.1:8000`。
- JWT Bearer：登录返回令牌，前端存 `localStorage` 的 `ssr_token`，请求拦截器附加请求头。
- 分页响应 `{ items, total, page, page_size }`；`page` 从 1 起，`page_size` 最大 100。
- 业务错误统一 `{ code, message, details? }`，`code` 常直接使用需求编号（如 `C3_BR-006`、`ST-029`）；参数校验失败为 422。

## 4 安装与启动
### 4.1 推荐方式：根目录 `start.bat` 一键启动
前提：已安装 Python 3.11+、Node.js 18+、MySQL 8.x，并知道本机 MySQL root 密码。在仓库根目录双击，或在 cmd 中执行：

```bat
start.bat
start.bat --no-browser
```
脚本依次执行（每一步幂等，重复运行安全）：

| 步骤 | 脚本动作 |
|---|---|
| 1 | 检查 Python 3.11+ 与 Node.js 18+，不满足则报错退出 |
| 2 | 若无 `backend/.venv` 则创建；按 `requirements.txt` 的 SHA-256 判断依赖变化并 `pip install` |
| 3 | 用 `bootstrap_db probe` 探测 MySQL；不可达时尝试用 `sc`/`net start` 启动 Windows MySQL 服务（约 15 次、每次约 1 秒） |
| 4 | `bootstrap_db check/ensure` 校验并生成 `.env`；首次提示输入 root 用户/密码，创建库 `smart_study_room`、账号 `study_app`（随机密码，仅写入被 Git 忽略的 `backend/.env`）与随机 JWT 密钥 |
| 5 | 执行 `python -m alembic upgrade head`，再幂等执行 `python -m scripts.seed` 与 `scripts.seed_demo` |
| 6 | `node_modules` 缺失时在 `frontend` 执行 `npm install` |
| 7 | 打开 `SSR Backend`（uvicorn 8000）与 `SSR Frontend`（vite 5173）窗口；等待 `/health` 与 5173 就绪后打开浏览器 |
说明：首次运行需联网装依赖；root 密码只使用一次、不写入文件；脚本不能替代 MySQL 服务端安装；`.env` 不可用时自动修复并备份为 `backend/.env.bak`；`backend/start.bat` 只启动后端（要求 `.venv` 与 `.env` 就绪，不建库、不迁移）。停止：`stop.bat`（关闭两个服务窗口并清理 8000、5173 监听进程，MySQL 保留运行）或各窗口 `Ctrl+C`。
### 4.2 手工三步启动
**第一步：MySQL。** Windows 以系统服务运行（本机服务名 `MySQL96`，以实际安装为准）：

```powershell
sc query MySQL96          # STATE : 4 RUNNING 表示已启动
net start MySQL96         # 需要管理员权限
```
首次建库建账号（先改 `backend/scripts/init_db.sql` 中的 `CHANGE_ME_APP_PASSWORD`）：

```bash
mysql -u root -p --default-character-set=utf8mb4 < backend/scripts/init_db.sql
```
**第二步：后端。**

```bash
cd backend
python -m venv .venv
source .venv/Scripts/activate          # PowerShell 用 .venv\Scripts\Activate.ps1
pip install -r requirements.txt
cp .env.example .env                   # 编辑 DATABASE_URL（study_app）与 JWT_SECRET_KEY
alembic upgrade head
python -m scripts.seed                 # admin/admin123、student/student123
python -m scripts.seed_demo            # 可选：2 间自习室、24 个座位（幂等）
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```
若 PowerShell 执行策略拦截 `Activate.ps1`，可跳过激活，直接执行 `.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload`。

**第三步：前端。**

```bash
cd frontend
npm install
npm run dev
```

## 5 功能说明
页面以 `frontend/src/router/index.ts` 与 `frontend/src/views/` 实际代码为准。前端共 22 个 `.vue` 视图：学生端 7 页、管理端 11 个业务页、系统管理员提示页 1 个、登录/注册各 1 页、404 页 1 个。
### 5.1 公共页面

| 页面 | 路由 | 主要功能 |
|---|---|---|
| 登录 | `/login` | 学生与管理员统一入口；学号/工号 + 密码；「记住我」仅缓存学号；开发期展示演示账号；连续失败临时锁定提示；注册入口 |
| 注册 | `/register` | 学生自助注册（后端只开放学生角色）；姓名、学号、密码、确认密码、可选联系方式；成功直接登录 |
| 404 | `/:pathMatch(.*)*` | 页面不存在提示与返回首页 |
### 5.2 学生端（7 页）

| 页面 | 路由 | 页面能做什么 |
|---|---|---|
| 首页 | `/student/home` | 问候、账户状态、累计违约与阈值提示；今日有效预约卡片（可直接签到/签退）；快捷入口；未读消息摘要；首次使用引导 |
| 预约座位 | `/student/booking` | 选择自习室、日期（今天起 7 天内）与时段（5 分钟粒度）；座位矩阵/列表视图；按类型/电源/靠窗筛选；座位详情展示可约、已被预约、维修中、停用、临时关闭与本人冲突；提交预约、失败原因与备选；时段已开始自动收敛到下一可约时段 |
| 我的预约 | `/student/reservations` | 状态标签页与计数；按日期、自习室筛选；服务端分页；签到、签退、取消（距开始 30 分钟以上）；对「已完成」预约提交评价（弹窗，一单一评） |
| 我的违约 | `/student/violations` | 查看本人违约记录、累计次数与账户状态；提供投诉入口；记录只读、不可撤销 |
| 我的投诉 | `/student/complaints` | 提交投诉（对象可为座位/自习室/预约单/用户）；按提交时间倒序查看进度；对「已处理」投诉由本人确认关闭 |
| 站内消息 | `/student/messages` | 按类型（预约、违约、投诉反馈、系统通知）筛选；服务端分页；未读数；单条/全部标为已读；点击跳转关联页面 |
| 个人资料 | `/student/profile` | 姓名、学号、角色、账户状态只读；修改联系方式；修改登录密码（原密码校验，改密后旧令牌失效）；展示受限/停用状态与预计解除时间 |
### 5.3 管理端（11 个业务页 + 系统管理员提示页）

| 页面 | 路由 | 页面能做什么 |
|---|---|---|
| 数据看板 | `/admin/dashboard` | 座位总数、当前时段使用中、今日预约、今日违约、受限账户数；各时段占用率、预约/违约趋势、用户违约 Top N；每 10 秒刷新并显示数据截至时间；失败保留上次数据 |

## 6 核心业务流程与业务规则
### 6.1 时间与预约硬约束

| 规则 | 取值 | 配置项 |
|---|---|---|
| 时间区间 | 左闭右开 `[s, e)`，相邻时段不算冲突 | `utils/time_utils.py::intervals_overlap` |
| 预约粒度 | 5 分钟，开始/结束均对齐，系统不自动取整 | `reservation_granularity_minutes` |
| 提前预约 | 最多提前 7 天（今天起 7 天内），开始时间须晚于当前时间 | `advance_booking_days` |
| 单次时长 | 最长 4 小时 | `max_reservation_hours` |
| 每人每日 | 最多 2 条有效预约（待使用/使用中） | `daily_reservation_limit` |
| 签到窗口 | `[开始前 15 分钟, 开始后 15 分钟)` | `checkin_early_minutes` / `checkin_late_minutes` |
| 违约阈值 / 限制期限 | 累计 3 次违约；自动限制 7 天（手动限制不自动解除） | `violation_threshold` / `restriction_days` |
| 无损取消 | 距开始时间大于 30 分钟（提交时刻 < 开始 − 30 分钟） | `cancel_before_minutes` |
| 看板刷新 / 统计块 | 每 10 秒读取一次；占用率按 30 分钟统计块 | `dashboard_refresh_seconds` / `dashboard_block_minutes` |
| 投诉自动关闭 | 已处理超过 7 天未关闭自动关闭（候选值，待业务确认） | `complaint_close_days` |
座位资源状态只有「可用 / 维修中 / 停用」；预约单状态只有「待使用 / 使用中 / 已取消 / 已完成 / 已违约」。有效预约仅为「待使用 / 使用中」，其余状态不占用时段。
### 6.2 预约状态流转
```text
创建预约 ──► 待使用 ──签到──► 使用中 ──签退──► 已完成
                │                 └─到达结束时间未签退──► 已完成（自动结束，不记违约）
                ├─开始后 15 分钟仍未签到──► 已违约（自动违约，累计次数）
                ├─用户无损取消（距开始 >30 分钟）──► 已取消
                └─管理员强制取消（仅待使用，须原因，不计违约）──► 已取消
```

| 操作 | 允许状态 | 结果与约束 |
|---|---|---|
| 创建预约 | — | 服务端重新校验 C1～C6；幂等键重复提交返回同一结果；冲突由槽位唯一约束与行锁兜底 |
| 签到 / 签退 | 待使用 / 使用中 | 签到仅在窗口内，成功转「使用中」；签退转「已完成」；未签退不产生违约 |
| 用户取消 | 待使用 | 距开始 >30 分钟可无损取消；不足 30 分钟拒绝，需管理员强制取消 |
| 管理员强制取消 / 手动违约 | 待使用 / 使用中 | 原因必填并写审计；强制取消不计违约、时段立即释放；手动违约累加次数 |
| 自动违约 / 自动结束 | 待使用 / 使用中 | 开始后 15 分钟未签到→已违约（同类幂等）；到达结束时间→已完成（`auto_completed=true`） |
### 6.3 签到、违约与黑名单联动
- 签到、签退、取消等判定一律以服务器时间为准（`time_utils.now()`），不使用客户端时间。
- 自动违约按「预约单 + 违约类型」去重，重复执行定时任务不会产生重复记录或重复累加次数。
- 累计有效违约达到 3 次时，自动写入 7 天期限黑名单并把账户置为「受限」；限制期间不能创建新预约，既有预约仍可正常签到使用。
- 自动限制到期由定时任务解除；**管理员手动加入的限制到期后不会自动解除**，必须由管理员手动解除并填写原因。
### 6.4 场地临时关闭流程
1. 管理员选择时间窗（可限定分区）并查询影响清单：`GET /api/v1/rooms/{room_id}/close-preview`。
2. 页面展示受影响座位数量与仍有效的预约列表（待使用/使用中）。
3. 管理员二次确认，前端把确认时的预约 id 列表提交给 `POST /api/v1/rooms/{room_id}/close`。
4. 后端重新计算影响清单；若与 `expected_reservation_ids` 不一致，返回 409「影响清单已变化」，要求重新查询。
5. 确认后写入 `room_closures` 时间窗记录；座位资源状态保持不变，窗口结束后自动失效。
6. 受影响预约默认**保留**；仅当管理员显式勾选「同时取消受影响预约」时，才批量置为「已取消」（记录原因，不计违约）并发送站内消息。
### 6.5 投诉状态流转（SM-04）

| 当前状态 | 允许动作 | 目标状态 |
|---|---|---|
| 待处理 | 管理员受理/处理 | 处理中 / 已处理 / 已驳回（处理说明必填） |
| 处理中 | 管理员处理 | 已处理 / 已驳回（记录处理人与处理时间） |
| 已处理 | 投诉人确认关闭 / 系统超时任务（超过 7 天，候选规则） | 已关闭 |
投诉对象为「座位 / 自习室 / 预约单 / 用户」的多态引用，数据库无法建普通外键，存在性由服务层校验。
### 6.6 权限与个人信息边界

| 边界 | 实现 |
|---|---|
| 学生只能操作本人预约 | 服务层校验 `reservation.user_id`，越权返回 403；学生端不显示他人姓名/学号 |
| 学生专属操作 | 预约、签到、签退、评价、投诉提交使用 `require_student` / `require_booking_user` |
| 管理端权限 | 业务管理接口使用 `require_admin`，仅「自习室管理员」可访问；系统管理员访问返回 403 并写越权审计 |
| 身份信息只读 / 脱敏 | 管理端不提供修改姓名、学号、密码、联系方式入口；联系方式服务端脱敏（手机号 `138****1234`、邮箱 `s******@zju.edu.cn`），本人读取本人资料保持原值 |
| 审计与令牌 | 强制取消、手动违约、黑名单、账户状态、资源与场地变更、越权尝试写 `audit_logs`；JWT HS256 默认 120 分钟，改密后 `token_version` 递增使旧令牌失效 |
### 6.7 定时任务

| 任务 | 周期 | 作用 |
|---|---|---|
| `auto_violation` | 1 分钟 | 扫描超时未签到预约并登记自动违约 |
| `auto_end_reservation` | 1 分钟 | 使用中且已到结束时间的预约转「已完成」 |
| `blacklist_expiry` | 10 分钟 | 解除到期的自动限制（跳过手动限制） |
| `complaint_auto_close` | 1 小时 | 关闭超期未确认的已处理投诉（候选规则） |
调度器时区 `Asia/Shanghai`，单实例、合并执行；测试环境可通过 `SCHEDULER_ENABLED=false` 关闭。

## 8 接口说明
### 8.1 通用约定
- 基础前缀 `/api/v1`；文档 `/docs`，OpenAPI `/openapi.json`，健康检查 `/health`（不在 `/api/v1` 下）。
- 认证：登录/注册返回 JWT；除登录、注册、健康检查外均需 `Authorization: Bearer <token>`。
- 权限：学生接口与学生本人数据校验用户身份；管理接口要求「自习室管理员」角色。
- 分页：`page`（≥1）、`page_size`（1～100，默认 20），响应 `PageResult`。
- 错误：`{ code, message, details? }`，`code` 使用需求编号或语义码；参数校验失败为 422。
- 路由模块共 13 个，按装饰器统计 `/api/v1` 下共 56 个端点（不含 `/health`）。
### 8.2 模块与代表性端点

| 模块 | 代表性端点（方法 路径） | 权限 |
|---|---|---|
| 认证 / 用户 | `POST /auth/register`、`POST /auth/login`、`GET /auth/me`；`GET/PATCH /users/me`、`PATCH /users/me/password`、`GET /users`、`PATCH /users/{user_id}/account-status` | 公开 / 本人 / 管理员 |

## 10 常见问题

| 现象 | 原因与处理 |
|---|---|
| 数据库连接失败 | 确认 MySQL 服务已启动；`study_app` 的 `localhost` 与 `127.0.0.1` 账号都已创建；`backend/.env` 密码与创建账号时一致；密码含 `@ : / ? #` 等字符需 URL 编码，建议 `openssl rand -hex 16` |
| Alembic 报 `'gbk' codec can't decode` | `alembic.ini` 在 Windows 上按系统 locale 读取，必须保持 ASCII，不要写中文注释 |
| 表已存在 / 没有 `alembic_version` | 本机重建：`mysql -u root -p -e "DROP DATABASE smart_study_room;"`，重跑 `scripts/init_db.sql`，再 `alembic upgrade head` 与 `python -m scripts.seed`；不要用 `alembic stamp head` 掩盖差异 |
| 前端接口 404/502 | 确认后端在 `127.0.0.1:8000` 运行；确认 `vite.config.ts` 的 `/api` 代理未被修改；检查 `alembic heads` 为 `f4b2d8c6a1e0` |
| PowerShell 无法识别 `uvicorn` / `Activate.ps1` 未签名 | 未激活虚拟环境或被执行策略拦截；用 `.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload`，或临时放行执行策略 |
| seed 中文输出乱码 | 设置 `PYTHONIOENCODING=utf-8`（`start.bat` 内已设置）；不影响数据库写入 |
| `net start MySQL96` 拒绝访问或服务名无效 | 需管理员权限；实际服务名用 `sc query state= all \| findstr /i MySQL` 查出后替换 |
| 端口 8000/5173 被占用 | `start.bat` 会跳过已监听端口；`stop.bat` 可确认并结束监听进程；也可用 `netstat -ano \| findstr :8000` 定位 |
```powershell
# PowerShell 执行策略拦截时（仅对当前窗口生效）
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1
```
