### 4. 后端测试

- 收集用例数：**120**（`pytest --collect-only -q` 与进度点一致）。
- 标准命令 `pytest -q`：**117 passed / 3 errors / 0 failed / 0 skipped**，exit=1。
  - 3 个 ERROR 全部是 `tests/test_bootstrap_db.py` 中使用 `tmp_path` 夹具的用例，且错误发生在 **fixture setup 阶段**：
    `PermissionError: [WinError 5] 拒绝访问。: C:\Users\20472\AppData\Local\Temp\dsh-21IeXX\pytest-of-20472`。
  - 根因（已定位）：pytest 用 `mkdir(mode=0o700)` 创建临时根目录；在 DSH Windows 沙箱下，`mode=0o700` 创建的目录 ACL 异常、连创建进程自身也无法 `scandir`（最小复现：`os.makedirs(p, mode=0o700)` + `os.scandir(p)` → WinError 5；默认 mode 正常）。这是**沙箱 ACL 缺陷，不是被测代码失败**。
  - 同一问题也导致 pytest 会话收尾 `cleanup_dead_symlinks` 崩溃，因此标准运行**没有打印 `N passed` 汇总行**（计数由进度点 + `--collect-only` 还原）。
- Lead 指定命令（`TMP/TEMP` 指向工作区 + `--basetemp=..\提交作业-软件\.work\pytest-base -p no:cacheprovider`）：exit=1，仍为 **117 passed / 3 errors**（`--basetemp` 会被 pytest 删除后以 0o700 重建，同样触发该缺陷）；日志 `logs\pytest-lead-cmd.log`。
- 规避沙箱 ACL 缺陷后的同套测试（仅把 `Path.mkdir` 的 mode 参数在内存中改为 0o777，不修改任何仓库文件）：exit=**0**，JUnit 汇总
  `tests=120 failures=0 errors=0 skipped=0`（`logs\pytest-junit.xml`，15.661s）。
- Lead 高权限复核日志 `logs\pytest-lead.log`：120 个进度点，**无 E / F**（即 120 通过）。
- 额外交叉验证：把 3 个受影响的用例函数体（`test_read_env_ignores_comments_and_strips_quotes`、`test_update_env_file_preserves_other_lines_and_backs_up`、`test_update_env_file_appends_missing_keys`）在普通权限临时目录下直接调用，**3/3 通过**。
- **结论：代码层面 120/120 通过；标准 pytest 在沙箱内因环境权限产生 3 个 setup ERROR，与代码缺陷无关。**
