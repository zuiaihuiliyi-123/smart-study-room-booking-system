# 智慧自习室预约与管理系统 使用说明

> 版本：V1.1（2026-11-05）  
> 适用场景：课程项目本地开发、联调与演示  
> 数据库方案：**每人本地 MySQL + Alembic 迁移**（方案 A）  
> 启动方式：Windows 推荐使用仓库根目录的 `start.bat` 一键启动（见 3.0）

## 1. 系统概览

| 项目 | 内容 |
|---|---|
| 系统目标 | 高校自习空间座位预约、使用管理、违约约束与数据分析 |
| 后端 | Python 3.11+、FastAPI、Pydantic 2、SQLAlchemy 2、Alembic、MySQL 8.4 LTS、JWT、APScheduler、Pytest |
| 前端 | Vue 3、TypeScript、Vite、Element Plus、Pinia、Vue Router、ECharts、Axios |
| 当前阶段 | 可演示闭环；M1～M7 业务接口均已实现，前端全部页面可演示 |

功能模块：

- M1 座位资源管理
- M2 预约管理
- M3 签到、签退与违约
- M4 查询
- M5 用户管理与投诉

- M7 站内通知

## 3. 首次启动

### 3.0 一键启动（Windows，推荐）

在仓库根目录双击 `start.bat`，或在 cmd 中执行：

```bat
start.bat
```

前提：Python 3.11+、Node.js 18+、MySQL 8.x 已安装，且知道本地 MySQL 的 root 密码。脚本会依次：

1. 检查 Python / Node.js；
2. 创建 `backend/.venv` 并安装后端依赖（`requirements.txt` 变化时自动重装）；
3. 探测 3306 端口，必要时尝试启动 Windows MySQL 服务；
4. 用 `backend/scripts/bootstrap_db.py` 检查/创建 `smart_study_room`、`study_app`，生成随机 JWT 密钥并写入 `backend/.env`（首次运行会提示输入 root 密码）；
5. 执行 `alembic upgrade head`，并幂等执行 `python -m scripts.seed`、`python -m scripts.seed_demo`；
6. 安装前端依赖（`node_modules` 缺失时），分别打开 `SSR Backend` / `SSR Frontend` 两个窗口；
7. 等待健康检查通过后打开 <http://127.0.0.1:5173>。

常用命令：

| 命令 | 作用 |
|---|---|
| `start.bat` | 完整启动并打开浏览器 |
| `start.bat --no-browser` | 启动但不打开浏览器 |
| `stop.bat` | 停止前后端（MySQL 服务保留运行） |

说明：

- 所有步骤幂等，重复运行不会重复建库、重复迁移或覆盖已有业务数据。
- `backend/.env` 不会被提交；需要修改时会先备份为 `backend/.env.bak`。
- 脚本只能创建数据库、账号、表结构和演示数据，**不能替代 MySQL 服务端的安装**。若本机没有 MySQL，请先安装：<https://dev.mysql.com/downloads/installer/>。
- 启动 MySQL 服务通常需要管理员权限；若脚本提示无法启动服务，请用管理员身份打开 cmd 执行 `net start <服务名>`，或在 `services.msc` 中启动。
- 第一次运行需要联网安装依赖。
- 需要手工排查时，仍可按 3.1～3.4 的步骤逐个启动；`backend/start.bat` 只启动后端，不会建库或迁移。

### 3.1 数据库

Windows 本机 MySQL 以**系统服务**方式运行，启动 MySQL 就是启动该服务（需要管理员权限的 PowerShell 或 CMD）：

```powershell
sc query MySQL96        # 查看状态，STATE : 4 RUNNING 表示已启动
net start MySQL96       # 启动
net stop  MySQL96       # 停止
```

- 服务名以本机实际安装为准：`sc query state= all | findstr /i MySQL` 可列出所有 MySQL 服务名；本机为 `MySQL96`。
- 服务名不同时，把上面命令中的 `MySQL96` 换成实际名称，并同步修改后文的启动说明。
- 也可以在 `services.msc` 图形界面中启动对应服务。
- 服务已在运行时，`net start` 会提示「服务已经启动」，属正常情况。

然后在 Git Bash 中连接验证：

```bash
mysql -u study_app -p -h 127.0.0.1 -P 3306 smart_study_room
```

连接成功后再按 [`数据库协作说明.md`](数据库协作说明.md) 完成：

1. 安装并启动 MySQL。
2. 修改 `backend/scripts/init_db.sql` 中的 `CHANGE_ME_APP_PASSWORD`。
3. 用 root 执行脚本，创建 `smart_study_room` 和 `study_app`。
4. 复制 `backend/.env.example` 为 `backend/.env`，填入自己的数据库密码。

快速命令：

```bash
cd backend

# 修改 scripts/init_db.sql 后执行
mysql -u root -p --default-character-set=utf8mb4 < scripts/init_db.sql

cp .env.example .env
# 编辑 .env 中的 DATABASE_URL
```

`.env` 已被 Git 忽略，不要提交；不要使用 root 运行应用。

### 3.2 后端

```bash
cd backend
python -m venv .venv
source .venv/Scripts/activate      # PowerShell 用 .venv\Scripts\Activate.ps1
pip install -r requirements.txt

alembic upgrade head
python -m scripts.seed
# 可选：演示自习室 / 分区 / 座位（幂等）
python -m scripts.seed_demo

uvicorn app.main:app --reload
```

**Windows 一键启动**：首次安装依赖、执行迁移和 seed 之后，日常启动不需要激活虚拟环境，直接运行：

```powershell
cd backend
.\start.bat
```

`start.bat` 会用 `.venv` 里的 Python 启动 `uvicorn app.main:app --reload --host 127.0.0.1 --port 8000`，并检查 `.venv` 与 `.env` 是否存在。注意：

- `.bat` 不受 PowerShell 执行策略限制，可直接在 PowerShell 或 CMD 中运行；双击也可以。
- 脚本不会自动执行 `alembic upgrade head`，拉取新代码后仍需手动迁移一次。
- 脚本内的提示信息使用英文：Windows cmd 可能按 OEM 代码页解析 `.bat`，中文信息在部分机器上会乱码或导致脚本解析失败。
- 用 Git Bash 时改为 `cmd //c start.bat`，或直接执行 `./.venv/Scripts/python.exe -m uvicorn app.main:app --reload`。

**虚拟环境激活失败时**（PowerShell 提示「未对文件 Activate.ps1 进行数字签名」）：这是执行策略限制，不是环境问题。最省事的方式是跳过激活，直接用解释器启动：

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

确实需要激活时，可对当前窗口临时放行，或对当前用户永久改为 `RemoteSigned`：

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1
```

访问：

- Swagger UI：<http://127.0.0.1:8000/docs>
- 健康检查：<http://127.0.0.1:8000/health>

如果 seed 的中文输出在 Git Bash 中乱码，可执行：

```bash
PYTHONIOENCODING=utf-8 python -m scripts.seed
```

### 3.3 前端

另开一个终端：

```bash
cd frontend
npm install
npm run dev
```

访问 <http://127.0.0.1:5173>。`frontend/.env.development` 默认 `VITE_USE_MOCK=false`，前端直连真实后端；Vite 已将 `/api` 代理到 `http://127.0.0.1:8000`。需要脱离后端独立演示时，把它改为 `true` 再重启即可（由 MSW 在浏览器内拦截）。

演示账户：

| 账号 | 密码 | 角色 |
|---|---|---|
| `admin` | `admin123` | 自习室管理员 |
| `student` | `student123` | 学生用户 |

> 登录页演示账号在开发服务器展示，生产构建默认隐藏；如需在生产预览中演示，构建前设置 `VITE_SHOW_DEMO_ACCOUNTS=true`。
>
> 学生自助注册默认开放。真实使用前可在 `backend/.env` 中设置 `REGISTRATION_ENABLED=false` 关闭自助注册（由管理员批量开户），或设置 `REGISTRATION_WHITELIST=S20260001,S20260002` 启用学号白名单；留空表示不限制。课程演示默认不限制学号。
>
> 登录失败锁定：同一学号在 15 分钟窗口内连续失败 5 次会临时锁定 15 分钟；可通过 `LOGIN_MAX_FAILURES` / `LOGIN_FAILURE_WINDOW_MINUTES` / `LOGIN_LOCK_MINUTES` 调整。不存在的学号同样计数，避免账号枚举。

### 3.4 日常启动顺序（每次开发 / 演示）

优先使用仓库根目录的 `start.bat`，它会按正确顺序完成下面三步。需要手工启动时，三个组件按以下顺序进行，前一个就绪再启动后一个：

| 顺序 | 组件 | 启动方式 | 就绪判据 |
|---|---|---|---|
| 1 | MySQL | `net start MySQL96`（管理员 PowerShell） | `sc query MySQL96` 显示 `RUNNING` |
| 2 | 后端 | `cd backend` 后 `.\start.bat`（仅后端） | 浏览器可打开 <http://127.0.0.1:8000/docs> |
| 3 | 前端 | `cd frontend` 后 `npm run dev` | 浏览器可打开 <http://127.0.0.1:5173> |

完整命令：

```powershell
# 终端 1：确保数据库已启动（已运行会提示「服务已经启动」）
net start MySQL96

# 终端 2：后端
cd backend
.\start.bat

# 终端 3：前端
cd frontend
npm run dev
```

停止顺序相反：先停前端（`Ctrl+C`），再停后端（`Ctrl+C`），MySQL 服务可保持运行。

如果拉取了新代码，启动后端前先执行：

```powershell
cd backend
.\.venv\Scripts\alembic.exe current      # 确认版本为 f2a3b4c5d6e7
.\.venv\Scripts\alembic.exe upgrade head
```

## 4. Alembic 迁移协作

### 4.1 角色分工

| 角色 | 职责 |
|---|---|
| 迁移负责人（建议固定一人，例如 D） | 修改模型后生成、审核、提交迁移；通知组员升级 |
| 其他组员 | 只执行 `alembic upgrade head`，不生成、不修改迁移 |

### 4.2 组员每天开始开发前

```bash
git pull
cd backend
alembic current
alembic upgrade head
```

- `alembic current` 显示 `f2a3b4c5d6e7 (head)`：数据库已是最新。
- 拉到了新的 `alembic/versions/*.py`：执行 `alembic upgrade head` 即可。
- 不需要重建数据库，也不要自己运行 `alembic revision --autogenerate`。

### 4.3 迁移负责人修改表结构

```bash
git pull
cd backend
alembic upgrade head

# 修改 app/models/ 下的模型

alembic revision --autogenerate -m "add xxx"
# 逐行审核新生成的迁移文件

alembic upgrade head
pytest
alembic check
```

`alembic check` 必须输出：

```text
No new upgrade operations detected.
```

然后提交**模型文件和迁移文件**，并通知组员执行：

```bash
git pull
cd backend
alembic upgrade head
```

### 4.4 迁移规则

- 表结构唯一来源是 `backend/alembic/versions/*.py`，不要手工改表后不写迁移。
- 已执行过的迁移不要修改；有变化就新建 revision。
- 一个迁移只做一件事；模型与迁移在同一个 PR 提交。
- `autogenerate` 不会处理数据迁移；给已有表加非空字段时要设置默认值或写 `op.execute(...)` 回填。
- 出现多个 head 时先协调，必要时 `alembic merge`，不要删除迁移文件。
- 共享库禁止随意 `alembic downgrade`；本机库可以删库重建。
- 不要编辑 `alembic.ini` 里的 `sqlalchemy.url`，实际连接串来自 `backend/.env`。

完整流程、常见错误与恢复方式见 [`数据库协作说明.md`](数据库协作说明.md)。

### 5.3 数据库已强制的约束

**唯一约束：**

| 表 | 约束 |
|---|---|
| `users` | `student_no` 唯一 |
| `rooms` | `name` 唯一 |
| `areas` | `(room_id, name)` 唯一 |
| `seats` | `(room_id, seat_no)` 唯一 |
| `reservations` | `(user_id, idempotency_key)` 唯一 |
| `reviews` | `reservation_id` 唯一（一单一评） |

**外键：**

- 预约单引用用户、座位
- 违约记录引用用户、预约单、操作人
- 评价引用用户、预约单
- 投诉引用提交人、处理人
- 黑名单引用用户、操作人
- 审计日志引用操作人（允许为空，用于未登录越权尝试）
- 站内消息引用用户
- 座位引用自习室、分区
- 分区引用自习室

**房间删除保护：**

- `areas.room_id`、`seats.room_id` 使用 `ON DELETE RESTRICT`，删除房间时不会级联删除分区和座位，避免历史记录失去关联对象。

**CHECK 约束：**

| 表 | 数据库强制规则 |
|---|---|
| `users` | 角色、账户状态取值合法；`violation_count >= 0` |
| `rooms` | `capacity >= 0`；`open_time < close_time` |
| `seats` | 资源状态只能是“可用/维修中/停用” |
| `reservations` | `start_time < end_time`；状态取值合法；幂等键非空 |
| `violation_records` | 类型只能是“自动违约/手动违约” |
| `reviews` | `score` 在 1～5 之间 |
| `complaints` | 投诉对象类型、状态取值合法 |
| `blacklist_entries` | 加入方式取值合法；`expire_at > start_at`；解除时间必须伴随解除原因 |
| `station_messages` | 消息类型取值合法 |

已用负向测试验证：非法角色、倒置时间段、评分 6、非法座位状态、非法黑名单方式、开放时间晚于关闭时间均会被数据库拒绝。

### 5.4 由服务层负责的业务规则

数据库约束只能保证结构合法性；以下规则在服务层实现，并由 `backend/tests` 覆盖：

| 规则 | 说明 |
|---|---|
| 预约时段重叠 | BR-005/BR-006；MySQL 无法用简单唯一约束表达任意区间重叠，需在事务中 `SELECT ... FOR UPDATE` 锁座位后查询并写入 |
| 有效预约状态 | 只有“待使用/使用中”占用时段；已取消/已完成/已违约不占用 |
| 预约时间规则 | 30 分钟粒度、最多提前 7 天、单次最长 4 小时、每日最多 2 条 |
| 签到/取消窗口 | 签到窗口、取消时限、自动违约触发点均按业务参数计算 |
| 自动违约幂等 | 同一预约单的自动违约只能生成一次；定时任务重复执行不得重复写入 |
| 违约次数一致性 | `users.violation_count` 必须与有效违约记录数量一致，需在同一事务内维护 |
| 黑名单生效逻辑 | 任一未解除且未到期记录使账户受限；手动限制不得被系统自动解除 |
| 评价资格 | 只能评价本人“已完成”的预约；数据库只保证一单一评，不保证提交人匹配 |
| 评价/违约归属 | `reviews.user_id`、`violation_records.user_id` 必须与预约单所属用户一致，当前靠服务层校验 |
| 座位分区归属 | 座位的 `area_id` 必须属于同一 `room_id`，当前靠服务层校验 |
| 投诉对象存在性 | `target_type + target_id` 是多态关联，数据库无法建普通外键，需服务层校验 |
| 审计只追加 | 审计日志不可修改/删除，当前靠服务层约束，未加数据库触发器；管理端提供只读查询页 `/admin/audit`，保留期由数据库运维策略决定 |
| 房间/座位不物理删除 | 已用 `RESTRICT` 降低级联风险；业务接口仍应只提供“停用”，不提供物理删除 |
| 角色权限边界 | 已提供 `require_student` 并记录越权审计；`require_admin` 已按 BR-018 收窄为仅业务管理员 R-02，系统管理员访问业务接口返回 403 |

### 5.5 需要业务确认或后续补充的内容

- `rooms.name` 当前是全局唯一。需求只要求“自习室标识唯一”，未明确要求名称全局唯一；如果不同位置可以同名，应改为 `(location, name)` 唯一。
- FR-042 的“可选附件”当前未建模；如本期要实现附件上传，需要增加附件表或附件字段。
- FR-041 的管理员评价处理目前只预留了评价内容字段，未建模处理状态/处理人；如需要保留处理痕迹，应后续补充。
- R-04 系统管理员的“参数配置”目前由 `backend/.env` / `Settings` 承载，没有 `system_configs` 表；如果要做页面化参数配置并审计变更，需要后续增加配置表。
- 当前数据库为 MySQL 9.6.0；团队标准为 8.4 LTS。两者对本项目 SQL 兼容，但建议统一版本，避免细节差异。

## 7. 常见问题

### 7.1 数据库连接失败

- 确认 MySQL 服务已启动。
- 确认 `study_app` 的 `localhost` 和 `127.0.0.1` 账号都已创建。
- 确认 `backend/.env` 的密码与创建账号时一致。
- 密码含 `@ : / ? #` 等字符时需 URL 编码，建议用 `openssl rand -hex 16` 生成十六进制密码。

### 7.2 Alembic 报 `'gbk' codec can't decode`

`alembic.ini` 在 Windows 上按系统 locale 读取，必须保持 ASCII；不要把中文注释写进 `alembic.ini`。

### 7.3 表已存在 / 没有 `alembic_version`

推荐本机重建：

```bash
mysql -u root -p -e "DROP DATABASE smart_study_room;"
mysql -u root -p --default-character-set=utf8mb4 < scripts/init_db.sql
cd backend
alembic upgrade head
python -m scripts.seed
```

不要用 `alembic stamp head` 掩盖结构差异。

### 7.4 前端接口 404/502

- 确认后端在 `127.0.0.1:8000` 启动。
- 确认 `frontend/vite.config.ts` 的 `/api` 代理未被修改。
- 若接口返回 404/501，先运行 `backend/.venv/Scripts/python.exe -m pytest -q` 与 `alembic heads`，确认迁移已到唯一 head（`f2a3b4c5d6e7`）且后端为新版本。

### 7.5 seed 中文输出乱码

```bash
PYTHONIOENCODING=utf-8 python -m scripts.seed
```

不影响数据库写入。

### 7.6 PowerShell 提示「无法将 uvicorn 项识别为 cmdlet」

原因是没有激活 `backend/.venv`，或者激活脚本被 PowerShell 执行策略拦截，导致 `.venv/Scripts` 不在 PATH 中。

```powershell
# 方式一：一键脚本
cd backend
.\start.bat

# 方式二：直接用解释器，不依赖激活
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload

# 方式三：临时放行执行策略后激活
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1
```

如果提示「未对文件 Activate.ps1 进行数字签名」，说明执行策略为 `Restricted`；方式一、方式二不受影响，可直接使用。

### 7.7 `net start MySQL96` 提示拒绝访问或服务不存在

- 「拒绝访问」：需要以管理员身份运行 PowerShell / CMD。
- 「服务名无效 / 指定的服务未安装」：本机 MySQL 服务名不是 `MySQL96`，用 `sc query state= all | findstr /i MySQL` 查出实际名称后替换；若没有任何输出，说明 MySQL 未安装或未注册为服务。
