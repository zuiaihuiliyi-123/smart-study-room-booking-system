### 1.2 通用约定

- 所有业务表的主键均为 `id INT AUTO_INCREMENT`。
- `created_at` 等时间字段由应用写入，数据库层没有 `CURRENT_TIMESTAMP` 默认值；`seats.near_window` 是唯一带数据库默认值的业务字段（默认 `0`）。
- `status`、`role`、`type` 等枚举字段使用 `VARCHAR` 存储中文值，并用 CHECK 约束限制取值，不使用 MySQL `ENUM`。
- `reserve_date` 使用 `DATE`，`start_time` / `end_time` 使用 `TIME`；预约占用区间为左闭右开 `[start_time, end_time)`。
- `DATETIME` 按服务器本地时间（UTC+8）解释，不处理夏令时。
- `tinyint(1)` 表示布尔值：`1` 为真，`0` 为假。
- 外键删除规则：
  - 自习室 → 分区、座位：`RESTRICT`，禁止级联删除历史资源。
  - 分区 → 座位：`SET NULL`，删除分区时座位保留，`area_id` 置空。
  - 其他外键：默认 `NO ACTION`（等效限制删除）。
- `alembic_version` 只记录迁移版本，不是业务表。

## 2. 表结构

### 2.1 `users`（用户）

- 对应需求：DR-001 用户
- 用途：保存学生、教师、自习室管理员、系统管理员账户及违约累计次数。
- 主键：`id`
- 唯一约束：`student_no`
- 外键：无
- 索引：`ix_users_student_no`（唯一）、`ix_users_role`、`ix_users_account_status`
- CHECK：`ck_user_role`、`ck_user_account_status`、`ck_user_violation_count`

| # | 字段 | 类型 | 可空 | 默认值 | 键 | 说明 |
|---:|---|---|:---:|---|---|---|
| 1 | `id` | `int` | 否 | — | PK | 用户标识，自增 |
| 2 | `name` | `varchar(50)` | 否 | — |  | 姓名 |
| 3 | `student_no` | `varchar(32)` | 否 | — | UQ | 学号/工号，全局唯一 |
| 4 | `password_hash` | `varchar(255)` | 否 | — |  | 密码哈希 |
| 5 | `role` | `varchar(20)` | 否 | — | IDX | 角色：学生用户 / 自习室管理员 / 教师用户 / 系统管理员 |
| 6 | `account_status` | `varchar(20)` | 否 | — | IDX | 账户状态：正常 / 受限 / 停用 |
| 7 | `violation_count` | `int` | 否 | — |  | 有效违约次数，须与违约记录一致 |
| 8 | `contact` | `varchar(100)` | 是 | `NULL` |  | 联系方式，学生唯一可自行修改的字段 |
| 9 | `created_at` | `datetime` | 否 | — |  | 创建时间 |

### 2.2 `rooms`（自习室）

- 对应需求：DR-002 自习室
- 用途：座位资源的顶层组织单位，保存开放时间、容量与启用状态。
- 主键：`id`
- 唯一约束：`name`
- 外键：无
- CHECK：`ck_room_capacity`、`ck_room_time_order`

| # | 字段 | 类型 | 可空 | 默认值 | 键 | 说明 |
|---:|---|---|:---:|---|---|---|
| 1 | `id` | `int` | 否 | — | PK | 自习室标识，自增 |
| 2 | `name` | `varchar(50)` | 否 | — | UQ | 自习室名称；当前全局唯一 |
| 3 | `location` | `varchar(100)` | 否 | — |  | 位置 |
| 4 | `open_time` | `varchar(5)` | 否 | — |  | 开放时间，格式 `HH:MM` |
| 5 | `close_time` | `varchar(5)` | 否 | — |  | 关闭时间，格式 `HH:MM` |
| 6 | `capacity` | `int` | 否 | — |  | 容量，`>= 0` |
| 7 | `enabled` | `tinyint(1)` | 否 | — |  | 是否启用；停用后其下座位不可预约 |
| 8 | `created_at` | `datetime` | 否 | — |  | 创建时间 |

> 注：需求只要求“自习室标识唯一”，当前 `name` 全局唯一是实现层的更严格约束；如果不同位置允许同名，应改为 `(location, name)` 唯一。

- 索引：`ix_seats_room_id`、`ix_seats_area_id`、`ix_seats_status`、`ix_seat_room_status`（`room_id`, `status`）

|---:|---|---|:---:|---|---|---|

| 2 | `room_id` | `int` | 否 | — | FK/IDX | 所属自习室 |
| 3 | `area_id` | `int` | 是 | `NULL` | FK/IDX | 所属分区；可为空 |
| 4 | `seat_no` | `varchar(20)` | 否 | — | UQ | 座位编号，同一自习室内唯一 |

### 2.5 `reservations`（预约单）

- 对应需求：DR-004 预约单
- 用途：记录“某座位在某时段被某用户占用”的唯一事实；占用区间为 `[start_time, end_time)`。
- 主键：`id`
- 唯一约束：`uq_reservation_idempotency`（`user_id`, `idempotency_key`）
- 外键：
  - `reservations_ibfk_1` → `seats.id`
  - `reservations_ibfk_2` → `users.id`
- 索引：`ix_reservations_user_id`、`ix_reservations_seat_id`、`ix_reservation_status`、`ix_reservation_seat_date`（`seat_id`, `reserve_date`）、`ix_reservation_user_date`（`user_id`, `reserve_date`）
- CHECK：`ck_reservation_time_order`、`ck_reservation_status`、`ck_reservation_idempotency_nonempty`

| # | 字段 | 类型 | 可空 | 默认值 | 键 | 说明 |
|---:|---|---|:---:|---|---|---|
| 1 | `id` | `int` | 否 | — | PK | 预约单标识，自增 |
| 2 | `user_id` | `int` | 否 | — | FK/IDX | 预约用户 |
| 3 | `seat_id` | `int` | 否 | — | FK/IDX | 预约座位 |
| 4 | `reserve_date` | `date` | 否 | — | IDX | 预约日期 |
| 5 | `start_time` | `time` | 否 | — |  | 开始时间 `s`（含） |
| 6 | `end_time` | `time` | 否 | — |  | 结束时间 `e`（不含）；必须大于 `start_time` |
| 7 | `status` | `varchar(20)` | 否 | — | IDX | 待使用 / 使用中 / 已完成 / 已取消 / 已违约 |
| 8 | `check_in_time` | `datetime` | 是 | `NULL` |  | 签到时间 |
| 9 | `check_out_time` | `datetime` | 是 | `NULL` |  | 签退时间 |
| 10 | `cancel_time` | `datetime` | 是 | `NULL` |  | 取消时间 |
| 11 | `cancel_reason` | `varchar(255)` | 是 | `NULL` |  | 取消原因 |
| 12 | `idempotency_key` | `varchar(64)` | 否 | — | UQ | 幂等键；同一用户内唯一 |
| 13 | `created_at` | `datetime` | 否 | — |  | 创建时间 |
| 14 | `updated_at` | `datetime` | 否 | — |  | 更新时间 |

> 注：`(user_id, idempotency_key)` 只能防止重复提交；同一座位的时间段重叠必须由服务层在事务中校验，数据库没有区间排他约束。

## 5. 数据库未强制、由服务层负责的规则

以下规则无法用当前数据库约束完整表达，必须在业务服务中实现；当前服务大多仍是 501 骨架：

- 同一座位/同一用户的预约时段重叠（BR-005、BR-006），需事务内 `SELECT ... FOR UPDATE`。
- 有效预约状态判断：只有“待使用/使用中”占用时段。
- 30 分钟粒度、提前 7 天、单次 4 小时、每日 2 条。
- 签到窗口、取消时限、自动违约触发与幂等。
- `users.violation_count` 与有效违约记录数量一致。
- 黑名单生效、手动限制不被自动解除。
- 评价必须由本人对“已完成”预约提交，且提交人需与预约单所属用户一致。
- 违约记录的用户需与预约单所属用户一致。
- 座位 `area_id` 必须属于同一 `room_id`。
- 投诉对象存在性（多态关联）。
- 审计日志只追加、不可更新/删除。
- 系统管理员不得处理业务数据（当前 `require_admin` 仍允许）。
- 房间/座位不提供物理删除；数据库已用 `RESTRICT` 防止房间删除级联丢失分区/座位，但业务接口仍应只提供“停用”。

详细说明见 [`系统使用说明.md`](系统使用说明.md) 第 5.4 节。
