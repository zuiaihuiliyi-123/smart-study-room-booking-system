## 1. 基线定义

本基线依据软件配置管理中的“基线”概念，将 2026-11-26 `main` 分支的软件状态冻结为一个可追溯、可复现的版本。自本基线起，后续对系统的修改均以本版本为参照，变更需提交、测试并重新标记版本。

## 2. 冻结内容

### 2.1 功能范围

- 学生端 7 个页面：主页、选座、我的预约、我的违约、投诉、消息、个人中心（采用顶栏导航 + 个人中心侧栏布局）。
- 管理端 11 个页面：数据看板、自习室管理、座位管理、预约管理、违约管理、投诉管理、评价管理、用户管理、黑名单管理、审计日志、个人资料。
- 后端 M1～M7 业务接口：认证与权限、自习室与座位、预约与签到签退、违约与黑名单、投诉、评价、站内消息、统计看板。
- 定时任务：自动违约、自动结束、黑名单到期解除、投诉自动关闭、登录尝试清理。
- 站内消息（本期仅站内，不接短信、邮件、微信）。

### 2.2 按需求文档排除的范围

FR-024 违约申诉、FR-033 记录导出、门禁/闸机/人脸识别、支付与押金、候补排队、代他人预约。

## 5. 已知限制

1. 学生端评价通过“我的预约”弹窗提交，无独立评价页面；管理端仅有只读评价管理页。
2. 管理端暂无独立站内消息页面。
3. 系统管理员与业务管理员的权限尚未按 BR-018 拆分。
4. Ruff 现有 35 项告警尚未清理，不影响运行。
5. 系统级联调测试（`tests/system/`）默认跳过，需启动后端并设置 `SYSTEM_BASE_URL` 后手动执行。

## 6. 基线变更控制

1. 基线标签 `v0.1.0-baseline` 一经发布不得移动或删除。
2. 基线后的修改须提交到 `main`，通过质量门禁后重新打标签（如 `v0.1.1-baseline`、`v1.0.0`）。
3. 回退时使用 `git checkout v0.1.0-baseline`，不得使用 `git reset --hard` 覆盖共享历史。
4. 数据库结构变更须附带 Alembic 迁移，并保证迁移链完整、测试通过。

## 7. 复现方式

```bash
git checkout v0.1.0-baseline

# 后端
cd backend
python -m pip install -r requirements.txt
alembic upgrade head
pytest

# 前端
cd ../frontend
npm ci
npm run type-check
npm run lint
npm run test
npm run build
```
