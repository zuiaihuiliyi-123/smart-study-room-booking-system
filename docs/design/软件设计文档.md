## 1. 引言

### 1.1 目的

说明系统的总体架构、模块划分、数据模型、接口契约、前端组织、关键业务流程与非功能设计，使新成员能够在不逐文件阅读代码的情况下理解系统，并为后续维护、测试和部署提供统一依据。

### 1.2 范围

覆盖：

- 后端 `backend/app`：API、服务、数据模型、认证授权、事务与并发、定时任务、缓存、异常处理。
- 前端 `frontend/src`：路由、页面、组件、状态管理、请求层、Mock。
- 数据库结构与迁移链。
- 当前运行与测试方式。

不覆盖：需求取舍的完整论证（见需求规格说明书）、逐条测试用例（见 `docs/测试用例清单-阶段2.md`）、UI 视觉规范细节（见 `docs/design/seat-booking-ui/`）。

### 1.3 术语

| 术语 | 含义 |
|---|---|
| 有效预约 | 状态为「待使用」或「使用中」的预约单 |
| 时段 | 左闭右开区间 `[start, end)`，粒度为 5 分钟 |
| 时段占位 | `reservation_slots` 中每 5 分钟一行，用于数据库唯一约束保证不重叠 |
| 幂等键 | 客户端生成的 `idempotency_key`，同一用户同一键只对应一张预约单 |
| 锁定 | 登录失败达到阈值后，对「学号 + 客户端 IP」临时拒绝登录 |
| 受限 | 账户状态，可登录但不可创建预约 |

## 2. 总体设计

### 2.1 系统上下文

```text
┌──────────────┐        HTTPS/JSON        ┌────────────────────┐
│ 浏览器        │  ──────────────────────▶ │ Vue 3 SPA           │
│ 学生/管理员   │  ◀────────────────────── │ (Vite 构建静态资源) │
└──────────────┘                          └─────────┬──────────┘
                                                     │ /api/v1（Axios）
                                                     ▼
                                          ┌────────────────────┐
                                          │ FastAPI 应用        │
                                          │ 认证/业务/定时任务  │
                                          └─────────┬──────────┘
                                                    │ SQLAlchemy 2.0
                                                    ▼
                                          ┌────────────────────┐
                                          │ MySQL（utf8mb4）    │
                                          └────────────────────┘
```

开发期可启用 MSW，在浏览器内拦截 `/api/v1` 请求，实现不启动后端的前端演示；生产构建不会打包 MSW。

### 2.2 逻辑架构

```text
前端
  views（页面） → components（领域组件） → utils/useXxx（组合式逻辑）
       │                    │
       └────────── api/*（Axios 封装） ──────────┐
                                                 │
后端                                             ▼
  api/v1/*（路由、参数、权限依赖）
       │
       ▼
  services/*（业务规则、事务、状态流转）
       │
       ▼
  models/*（SQLAlchemy ORM） ── schemas/*（Pydantic 请求/响应）
       │
       ▼
  MySQL

旁路组件：
  core/*（配置、数据库、安全、异常、缓存、重试）
  tasks/*（APScheduler 定时任务 + task_executions 执行记录）
  utils/*（时间、脱敏、分页）
```

## 3. 后端设计

### 3.1 目录结构

```text
backend/
├── app/
│   ├── main.py              # create_app、CORS、缓存中间件、健康检查
│   ├── api/
│   │   ├── router.py        # 汇总 13 个路由模块
│   │   └── v1/              # auth/users/rooms/seats/reservations/attendance/
│   │                        # violations/reviews/complaints/blacklist/audit/
│   │                        # dashboard/messages
│   ├── core/                # config/database/security/dependencies/
│   │                        # exceptions/transactions/cache/db_retry
│   ├── models/              # 16 张表的 ORM 模型
│   ├── schemas/             # 请求/响应/分页模型
│   ├── services/            # 业务规则与事务边界
│   ├── tasks/               # APScheduler 任务、运行包装、执行记录
│   └── utils/               # time_utils/masking/pagination
├── alembic/                 # 迁移脚本（单链）
├── tests/                   # 回归 + qa + whitebox
└── requirements.txt
```

### 3.2 分层职责

| 层 | 职责 | 约束 |
|---|---|---|
| `api/v1` | 路由、查询参数、权限依赖、调用 service | 不写业务规则；不直接操作 ORM 明细 |
| `services` | 业务校验、状态流转、事务、审计、通知 | 对外抛 `BusinessError`；事务边界清晰 |
| `models` | 表结构、枚举、约束 | 不包含业务判断 |
| `schemas` | 输入校验、输出序列化 | 只做格式/范围校验 |
| `core` | 基础设施 | 不依赖具体业务模块 |
| `tasks` | 周期任务 | 幂等、单条失败隔离 |

依赖方向：`api → services → models/schemas/core`，`tasks → services`；禁止反向依赖。

### 3.3 请求处理链

```text
请求
 → CORS 中间件
 → 看板缓存清理中间件（写请求成功后 clear_dashboard_cache）
 → 路由匹配
 → 认证依赖 get_current_user（JWT + token_version + 账户停用检查）
 → 角色依赖 require_admin / require_student / require_booking_user
 → 限流依赖（登录/注册，按 IP 固定窗口）
 → Pydantic 参数校验
 → service（业务规则 + 事务）
 → 响应序列化
 → 异常处理器（BusinessError / IntegrityError / HTTPException / 校验错误）
```

### 3.4 认证与授权

- 登录：学号/工号 + 口令，Argon2 校验；成功签发 JWT。
- JWT claims：`sub`（用户 ID）、`role`、`ver`（`token_version`）、`iat`、`exp`。
- 令牌撤销：登出、改密递增 `token_version`，旧令牌立即失效。
- 依赖：
  - `get_current_user`：解析令牌、校验版本、拒绝停用账户。
  - `require_admin`：仅「自习室管理员」；系统管理员本版无业务权限。
  - `require_student`：仅学生，用于投诉、评价等。
  - `require_booking_user`：仅学生可预约与签到/签退。
- 越权访问会写审计日志（`_record_unauthorized`）。
- 登录/注册限流：数据库固定窗口计数；登录失败锁定按「学号 + 客户端 IP」。

### 3.5 事务、并发与幂等

**事务**

- 每个请求一个 `Session`（`get_db`），请求结束关闭。
- 多表写操作使用 `core/transactions.transaction(db)`：成功提交、异常回滚。
- 通知在事务提交后发送；`notify_safe` 失败不影响已成功的核心业务。

**并发控制**

| 场景 | 机制 |
|---|---|
| 创建预约 | 锁定座位行、用户行（`SELECT ... FOR UPDATE`，MySQL 生效） |
| 时段冲突 | `reservation_slots` 唯一约束 `(seat_id, slot_start)`、`(user_id, slot_start)` |
| 签到/签退/取消 | 条件更新 `UPDATE ... WHERE status = 期望状态`，未命中返回 409 |
| 场地关闭 vs 新预约 | 关闭前锁定座位行；写入关闭记录后复核影响清单，变化则回滚 409 |
| 黑名单并发加入 | `blacklist_entries.active_user_id` 唯一约束兜底 |
| 限流并发 | 先 UPDATE 自增；首次插入撞唯一约束时回退为自增 |
| 重复提交 | 幂等键唯一约束 + 重放返回原预约单 |

**幂等**

- 预约创建：同一用户 + `idempotency_key` 唯一；键相同但座位/时段不同返回 `IDEMPOTENCY_KEY_REUSED`。
- 幂等重放只返回既有预约，不重复发送“预约成功”消息。
- 自动违约：`(reservation_id, type)` 唯一，重复扫描不重复累计。
- 定时任务整体可重复执行。

### 3.6 限流与登录锁定

| 机制 | 存储 | 规则 |
|---|---|---|
| 登录限流 | `rate_limit_buckets` | 默认 10 次/分/IP，429 + `Retry-After` |
| 注册限流 | `rate_limit_buckets` | 默认 5 次/分/IP |
| 登录失败锁定 | `login_attempts` | 15 分钟内失败 5 次 → 锁定 15 分钟；键为「学号 + IP」 |
| 失败计数清理 | 定时任务 | 保留 30 天，每日 03:30 清理 |

不存在的学号同样计数，避免账号枚举；锁定按 IP 隔离，防止他人从其他地址锁死受害者。

### 3.7 异常与错误响应

统一结构：

```json
{
  "code": "C6_BR-002",
  "message": "只能预约今天起未来 7 天内的时段",
  "details": { "allowed_from": "...", "allowed_to": "..." }
}
```

| 异常 | 处理 |
|---|---|
| `BusinessError` | 按其 `code/status_code/details/headers` 返回 |
| `IntegrityError` | 409 `DATA_CONFLICT`，不泄露 SQL |
| `HTTPException` | 转为 `HTTP_<status>` + detail |
| 请求校验失败 | 422 `VALIDATION_ERROR`，中文可操作提示 + 原始错误明细 |

### 3.8 定时任务

任务注册在 `app/tasks/scheduler.py`，执行结果写入 `task_executions`。

| 任务 ID | 频率 | 作用 |
|---|---|---|
| `auto_violation` | 每分钟 | 超时未签到 → 自动违约 |
| `auto_end_reservation` | 每分钟 | 使用中且已到结束时间 → 已完成 |
| `blacklist_expiry` | 每 10 分钟 | 自动限制到期解除、违约计数清零 |
| `complaint_auto_close` | 每小时 | 已处理投诉超 7 天自动关闭 |
| `login_attempt_cleanup` | 每日 03:30 | 清理过期登录失败计数 |

任务包装 `run_scheduled_task` 提供重试、退避、执行记录；单条业务失败不影响其他记录。

> 当前实现每个后端进程都会启动调度器；多 worker 部署时应只保留一个调度进程，详见 §11。

### 3.9 缓存与时间口径

- 看板概览使用进程内 TTL 缓存（默认 10 秒），写请求成功后清空当前进程缓存。
- 业务时间统一为 `Asia/Shanghai` 的 naive datetime；数据库 `DATETIME` 不存时区。
- 预约、签到窗口、取消截止时间均以服务端时间为准。
- 管理端联系方式在服务端脱敏（`utils/masking.py`），不依赖前端遮挡。

## 4. 数据设计

### 4.1 实体关系

```text
User 1 ── n Reservation n ── 1 Seat n ── 1 Room 1 ── n Area
  │              │ 1                    │
  │              └── n ReservationSlot   └── n RoomClosure
  ├── n ViolationRecord n ── 1 Reservation
  ├── n BlacklistEntry
  ├── n Complaint（target 可为 Seat/Room/Reservation/User）
  ├── n Review 1 ── 1 Reservation
  ├── n StationMessage
  └── n AuditLog（operator）

LoginAttempt：独立表，不关联 User（防止账号枚举）
RateLimitBucket：按 scope + key + window 计数
TaskExecution：定时任务执行记录
```

### 4.2 表清单

| 表 | 用途 | 关键约束/索引 |
|---|---|---|
| `users` | 学生/管理员账户 | `student_no` 唯一；角色、账户状态 CHECK |
| `rooms` | 自习室 | `name` 唯一；开放时间 CHECK |
| `areas` | 自习室分区 | `(room_id, name)` 唯一 |
| `seats` | 座位资源 | `(room_id, seat_no)` 唯一；状态仅可用/维修中/停用 |
| `room_closures` | 临时关闭窗口 | `start_at < end_at`；按 room/area 生效 |
| `reservations` | 预约单 | `(user_id, idempotency_key)` 唯一；时间顺序 CHECK |
| `reservation_slots` | 5 分钟时段占位 | `(seat_id, slot_start)`、`(user_id, slot_start)` 唯一 |
| `violation_records` | 违约记录 | `(reservation_id, type)` 唯一 |
| `blacklist_entries` | 黑名单/限制 | `active_user_id` 唯一；解除必须有原因 |
| `complaints` | 投诉 | 目标类型/状态 CHECK；`(user_id, status)` 索引 |
| `reviews` | 评价 | `reservation_id` 唯一（一单一评） |
| `station_messages` | 站内消息 | 按用户查询、未读计数索引 |
| `audit_logs` | 审计日志 | 只追加；按操作类型/操作者/时间筛选 |
| `login_attempts` | 登录失败计数 | 主键 `(student_no, ip)`；`updated_at` 索引 |
| `rate_limit_buckets` | 限流窗口计数 | `(scope, key, window_start)` 唯一 |
| `task_executions` | 定时任务执行记录 | 任务名/状态/时间 |

### 4.3 状态机

**预约单（SM-02）**

```text
待使用 ──签到──▶ 使用中 ──签退/自动结束──▶ 已完成
   │                  │
   │                  └──管理员手动违约──▶ 已违约
   ├──用户取消/强制取消──▶ 已取消
   └──超时未签到（自动）──▶ 已违约
```

已完成、已取消、已违约均为终态；取消/违约/完成时删除 `reservation_slots` 释放时段。

**账户状态（SM-03）**

```text
正常 ──触发黑名单/自动限制──▶ 受限 ──解除/到期──▶ 正常
正常/受限 ──管理员停用──▶ 停用 ──管理员恢复──▶ 正常（仍有限制时拒绝恢复）
```

停用账户不能登录；受限账户可登录但不可创建预约。

**座位资源状态（SM-01）**：可用 / 维修中 / 停用；不表示“已预约/使用中”。

**投诉（SM-04）**

```text
待处理 ──受理──▶ 处理中 ──录入结果──▶ 已处理 ──投诉人确认/超时──▶ 已关闭
   └──驳回──▶ 已驳回
```

## 5. 接口设计

### 5.1 通用约定

- 基础路径：`/api/v1`；健康检查 `/health`。
- 认证：`Authorization: Bearer <JWT>`。
- 分页：`page`（从 1 开始）、`page_size`（默认 20，最大 100），响应 `{items,total,page,page_size}`。
- 时间：请求/响应均为 `YYYY-MM-DD`、`HH:MM` 或 `YYYY-MM-DDTHH:MM:SS`（业务时区）。
- 错误：见 §3.7；幂等创建失败可重试，冲突用 409 区分。
- 权限标记：公开 / 登录 / 学生 / 管理员。

### 5.2 端点清单

#### 认证与用户

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| POST | `/auth/register` | 公开 | 学生注册（受开关/白名单控制） |
| POST | `/auth/login` | 公开 | 登录，签发 JWT |
| POST | `/auth/logout` | 登录 | 递增令牌版本 |
| GET | `/auth/me` | 登录 | 当前用户 |
| GET | `/users/me` | 登录 | 本人资料 |
| PATCH | `/users/me` | 登录 | 修改本人联系方式 |
| PATCH | `/users/me/password` | 登录 | 改密，旧令牌失效 |
| GET | `/users` | 管理员 | 用户列表与筛选 |
| PATCH | `/users/{user_id}/account-status` | 管理员 | 停用/恢复学生账户 |

#### 自习室、分区与座位

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/rooms` | 登录 | 自习室列表 |
| POST | `/rooms` | 管理员 | 新建自习室 |
| PATCH | `/rooms/{room_id}` | 管理员 | 修改自习室 |
| DELETE | `/rooms/{room_id}` | 管理员 | 删除无预约历史的空自习室 |
| GET | `/rooms/{room_id}/areas` | 登录 | 分区列表 |
| POST | `/rooms/{room_id}/areas` | 管理员 | 新建分区 |
| GET | `/rooms/{room_id}/close-preview` | 管理员 | 关闭影响清单（只读） |
| POST | `/rooms/{room_id}/close` | 管理员 | 二次确认后关闭 |
| GET | `/rooms/{room_id}/closures` | 登录 | 未结束的关闭记录 |
| DELETE | `/rooms/{room_id}/closures/{closure_id}` | 管理员 | 提前解除关闭 |
| GET | `/rooms/{room_id}/seats` | 登录 | 座位列表（资源状态） |
| GET | `/seats/occupancy` | 管理员 | 资源状态 + 时段占用 |
| GET | `/seats/conflicts` | 管理员 | 状态调整冲突清单 |
| POST | `/seats` | 管理员 | 新增座位 |

Pinia 只保存跨页面状态：

- 响应拦截器：
  - 取消请求静默；
  - 401 清理两种存储并跳登录（`skipAuthRedirect` 可跳过，用于登出）；
  - `silent` 控制是否弹 `ElMessage`（看板轮询使用）。

- 默认开发模式 `VITE_USE_MOCK=false`，直连 FastAPI。

- SCSS 变量 + Element Plus 主题变量；支持浅色/暗色。

- 响应式布局集中在 `assets/styles`，页面不硬编码颜色。

## 7. 关键流程设计

### 7.1 创建预约

```text
客户端提交幂等键
 → 查同用户同键：存在且内容一致 → 直接返回原预约
 → 存在但内容不同 → 409 IDEMPOTENCY_KEY_REUSED
 → 开启事务
 → 锁定座位行、用户行
 → C1～C6 校验（资源/开放时间/临时关闭/每日次数/时段冲突）
 → 插入预约单
 → 按 5 分钟生成 reservation_slots（唯一约束检查冲突）
 → 提交
 → 仅新建时发送“预约成功”站内消息
```

### 7.2 取消、签到、签退

- 取消：仅本人「待使用」且距开始 ≥30 分钟；条件更新状态，释放时段。
- 签到：窗口 `[开始-15min, 开始+15min)`；条件更新为「使用中」。
- 签退：仅「使用中」；条件更新为「已完成」，释放时段。
- 并发下未命中条件更新的请求返回 409，并读取最新状态给出准确提示。

### 7.3 自动违约与自动结束

- 自动违约：扫描日期 ≤ 今天、状态「待使用」、学生预约；超过开始+15 分钟仍待使用 → 写违约记录、状态「已违约」、释放时段、按阈值触发黑名单。
- 自动结束：扫描「使用中」且结束时间已到 → 「已完成」、`auto_completed=True`、签退时间=结束时间、释放时段；不产生违约。

### 7.4 场地临时关闭

```text
GET close-preview（只读影响清单）
 → 管理员二次确认，提交 expected_reservation_ids
 → 锁定关闭范围内座位行
 → 读取影响清单并与 expected 比对；不一致 → 409，要求重新预览
 → 写入关闭记录
 → 复核影响清单；若期间有新预约落库 → 回滚 409
 → 按选择保留或批量取消预约，写审计
```

### 7.5 黑名单与阈值

- 有效违约数达到 3 → 自动创建 7 天限制；同一用户最多一条生效记录（`active_user_id` 唯一）。
- 自动限制到期由任务解除，违约计数清零；手动限制到期不自动解除。
- 加入/解除均写审计并发送站内消息。

### 7.6 投诉状态流转

- 学生提交 → 待处理；管理员受理 → 处理中，或驳回 → 已驳回；处理中录入结果 → 已处理。
- 已处理可由投诉人确认关闭，或超 7 天由任务自动关闭并发送消息。
- 管理员不能直接置为已关闭。

### 7.7 看板刷新

- 前端每 10 秒拉取概览/图表，页面显示“数据截至时间”。
- 后端概览使用 10 秒进程内缓存；写请求成功后清缓存。
- 失败时保留上一份数据并在页面内提示，不使用全屏错误。

## 8. 非功能设计

### 8.1 安全

- 口令 Argon2 不可逆存储；JWT 密钥启动校验，拒绝占位符。
- 管理端联系方式服务端脱敏；日志不记录口令/令牌。
- 角色权限在服务端校验，前端守卫仅改善体验。
- 登录/注册限流；登录失败锁定按 IP 隔离。
- 生产环境关闭接口文档。
- 审计日志只追加，不提供修改/删除。

### 8.2 性能

- 数据库连接池显式配置（pool_size/max_overflow/timeout/recycle）。
- 预约冲突使用唯一约束而非仅靠查询。
- 列表接口统一分页；看板短缓存合并 10 秒内并发查询。
- 前端路由懒加载，ECharts/Element Plus/Vue 独立拆包。

### 8.3 可靠性

- 事务边界明确；失败回滚。
- 数据库死锁/锁等待按配置重试。
- 定时任务幂等、可重复执行、单条失败隔离，并记录 `task_executions`。
- 站内消息失败不回滚核心业务。

### 8.4 隐私与合规

- 学生端不展示其他用户姓名/学号。
- 管理端手机号/邮箱脱敏。
- 管理员手动违约记录操作者与原因。
- 审计日志覆盖关键管理与越权操作。

### 8.5 可维护性

- 前后端按业务模块拆分；服务层集中业务规则。
- 枚举、状态与参数集中在 `enums.py`、`config.py`。
- 数据库迁移单链，禁止修改历史迁移。
- 测试分三层：回归、QA 边界/并发、白盒分支。
