## 1. 测试目标

验证系统在“接近真实部署”的条件下能否完整跑通，而不是只验证单个函数或 Mock 数据：

1. 数据库迁移、种子数据、真实 MySQL 可正常工作。
2. 学生与管理员通过真实 HTTP 接口完成预约、取消、签到/签退、违约、黑名单、投诉、消息、看板、审计等业务闭环。
3. 并发提交在真实 MySQL 行锁与唯一约束下行为正确。
4. 真实浏览器可以登录并完成选座预约、取消、管理端查看。
5. 生产配置（`APP_ENV=production`）下接口文档关闭，鉴权边界生效。

## 4. 执行命令

```bash
# 1. 启动隔离 MySQL（3307）并创建空库后，执行迁移与种子
cd backend
DATABASE_URL="mysql+pymysql://root:@127.0.0.1:3307/ssr_sys?charset=utf8mb4" \
  .venv/Scripts/alembic.exe upgrade head
DATABASE_URL="..." .venv/Scripts/python.exe -m scripts.seed
DATABASE_URL="..." .venv/Scripts/python.exe -m scripts.seed_demo

# 2. 启动后端（生产模式，关闭调度器避免干扰）
DATABASE_URL="..." APP_ENV=production SCHEDULER_ENABLED=false \
  CORS_ORIGINS='["http://127.0.0.1:5180"]' \
  .venv/Scripts/python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8010

# 3. 启动前端（真实 API）
cd frontend
VITE_API_BASE_URL="http://127.0.0.1:8010/api/v1" VITE_USE_MOCK=false \
  npx vite --host 127.0.0.1 --port 5180

# 4. API 系统测试
cd backend
SYSTEM_BASE_URL="http://127.0.0.1:8010" \
  .venv/Scripts/python.exe -m pytest tests/system -q

# 5. 浏览器系统测试
cd frontend
PLAYWRIGHT_CHROMIUM_PATH="<本机 Chromium 路径>" \
  npx playwright test --config playwright.system.config.ts
```

> `tests/system` 默认跳过；只有显式设置 `SYSTEM_BASE_URL` 才连接真实服务，避免污染日常回归。

## 5. 测试过程中修正的假设

系统测试直接暴露了若干“文档/测试假设与真实接口契约不一致”的问题。它们不是产品缺陷，测试脚本已按实际契约修正：

1. `available-seats` 必须携带 `room_id`，否则 422。
2. 取消、签到、签退接口返回 `{"message": ...}`，预约状态需再从本人预约列表读取。
3. 投诉不能从「待处理」直接改为「已处理」，必须先「处理中」；符合状态机设计。
4. Playwright 本机浏览器/ffmpeg 版本与当前测试库不匹配，改用已安装 Chromium 并关闭录屏；属于环境问题。

## 6. 未覆盖与限制

1. **定时任务未在系统级运行**：为避免干扰测试数据，后端设置 `SCHEDULER_ENABLED=false`；自动违约、自动结束、限制到期等由单元/白盒测试覆盖。
2. **单 worker**：未验证多 worker 下调度器重复执行、限流共享等部署行为。
3. **未做性能/压力测试**：没有并发登录、看板高 QPS、长时间稳定性数据。
4. **未做安全渗透**：未测试 XSS/CSRF、令牌窃取、代理伪造 IP 等。
5. **浏览器版本较旧**：使用本机已有 Chromium，未覆盖最新 Chromium/Firefox/WebKit/移动端。
6. **数据库版本差异**：使用 MySQL 8.0.21；开发环境为 MySQL 9.6，生产版本仍需按实际环境复验。
7. **未覆盖管理端全部页面**：浏览器测试覆盖看板与预约管理；自习室/座位/黑名单/审计等由 API 与白盒测试覆盖。

## 7. 结论

- 真实 MySQL + 真实后端 + 真实浏览器条件下，系统核心业务闭环可用。
- 预约幂等、并发唯一性、黑名单限制、投诉状态机、签到/签退窗口、生产文档关闭均按设计工作。
- 本轮未发现需要修复的业务缺陷；主要剩余风险集中在部署形态（多 worker 调度、CI、Docker/Nginx）与性能/安全专项测试，见设计文档 §11。
