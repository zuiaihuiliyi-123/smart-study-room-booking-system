# 智慧自习室预约与管理系统 · 三周开发计划（3-Week Delivery Plan）

| 项目 | 内容 |
|---|---|
| 文档版本 | v1.0（三周冲刺版） |
| 编制日期 | 2026-10-29 |
| 适用基线 | 当前 `main`：FastAPI + Vue 3 的 501 开发骨架 |
| 团队规模 | 4 人：A 预约/违约后端、B 资源/治理后端、C 前端、D 平台/质量 |
| 计划周期 | 15 个工作日；建议 2026-11-02（周一）～ 2026-11-20（周五） |

> **结论先行**
>
> 1. 3 周完成原 6 周计划的全量内容不现实。本计划把 6 周压缩为 **P0 基座（3 天）→ 五条垂直切片（10 天）→ 硬化验收（2 天）**，并明确砍掉评价、投诉自动关闭、审计查询页、E2E、严格 mypy、完整压测等非闭环项。

## 0. 计划前提与可行性

### 0.1 时间与产能假设

- 按 15 个工作日排期，周末只作缓冲，不排主线任务。
- 建议日历：W1 11/02～11/06，W2 11/09～11/13，W3 11/16～11/20；若启动日不同，整体平移。
- 4 人 × 15 天 = 60 人日（按 8 小时/人日）。若每人每天有效投入只有 6 小时，实际产能约 45 人日。

### 0.2 工作量估算与取舍

| 工作流 | Must-have 估算（人日） | 说明 |
|---|---:|---|
| P0 基座冻结 | 8 | 迁移、seed、错误四类、鉴权、OpenAPI、测试、CI、time_utils |

| M5 最小治理 | 7 | 用户资料、投诉、黑名单、审计；评价延后 |

**结论**：按全职投入，必须砍掉约 5～6 人日；本计划已把评价（2）、投诉自动关闭（1）、审计查询页（1）、看板美化/二级筛选（1）、E2E/严格 mypy（1）移出 Must-have。若实际只能 6 小时/天，产能 45 人日，**3 周不可行**，必须走 Plan B。

### 0.3 三条硬约束

1. **共享内核只允许一套**：`time_utils.py`、`availability_service.py`、`exceptions.py`、`dependencies.py`、`audit_service.py`、`request.ts`、`types/index.ts` 不允许各写一份。
2. **先契约后页面**：前端只对接 `/openapi.json` 与已冻结的 TS 类型，不猜字段、不在前端复制 C1～C6。
3. **每个阶段有出口门禁**：不达标不进入下一阶段；每周五演示并记录证据。

### 3.2 统一错误四类（P0-03）

| code | HTTP | 场景 | 前端行为 |
|---|---:|---|---|
| `UNAUTHENTICATED` | 401 | 未登录、token 失效、账户停用 | 清理 token，跳登录 |
| `FORBIDDEN` | 403 | 学生调管理员接口、越权查他人数据 | 提示无权限，不重试 |
| `PRECONDITION_FAILED` | 412 | 账户受限、预约状态不允许、签到窗口未到、非“使用中” | 提示条件不满足，刷新状态 |
| `RULE_VIOLATION` | 400 | C1～C6、粒度未对齐、超过 7 天/4 小时/2 条、取消超时 | 展示具体规则项，允许修改 |
| `CONFLICT` | 409 | 座位时段被占、并发冲突、同一幂等键不同请求 | 提示冲突，刷新可预约数据 |
| `VALIDATION_ERROR` | 422 | Pydantic 参数校验失败 | 展示字段错误（由框架/统一处理器返回） |

统一 JSON：

```json
{
  "code": "RULE_VIOLATION",
  "message": "该座位在该时段已被预约",
  "detail": { "rule": "C3", "seat_id": 12 }
}
```

要求：
- `BusinessError` 支持 `code`、`message`、`detail`、`status_code`。
- 为 FastAPI `RequestValidationError` 增加统一处理器，避免 422 默认结构与四类不一致。
- 保留 501 处理器，但 Must-have 服务在对应阶段出口不得再出现 `NotImplementedError`。

## 附录 A：不可变业务约定（写进团队公约）

1. 时间区间统一左闭右开 `[s, e)`；相邻不冲突。

8. 自动违约记录与预约单按“预约单 + 类型”去重；重复扫描不得重复累加。
9. 违约阈值 3 次 → 受限 7 天；手动限制到期不得自动解除；已有未来预约不自动取消。
10. 管理员不分级；系统管理员本轮不得处理业务数据。
11. FR-024 申诉、FR-033 导出不实现；FR-060 仅站内消息。
12. 所有时间判断以服务器本地时间（UTC+8）为准。
