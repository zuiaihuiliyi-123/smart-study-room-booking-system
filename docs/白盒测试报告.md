## 4. 发现的问题与观察

本轮白盒测试**未发现新的 P0/P1 业务缺陷**。以下为测试过程中值得记录的观察，均不构成本轮修复项：

1. **SQLite 下 SAVEPOINT 语义与 MySQL 不同**：在无外层事务时，`begin_nested()` 释放会提交 SQLite 事务。`restrict_if_threshold(commit=False)` 在真实调用链中已有外层事务（违约记录写入），不影响 MySQL/SQLite 生产行为；测试中已按真实调用条件断言。
2. **`rate_limit_service._window_start` 只对齐秒**：当前唯一使用场景 `window_seconds=60` 与分钟对齐等价；若未来引入非 60 秒窗口，需要按 `timestamp % window_seconds` 重新对齐。属于低风险实现观察。
3. **`core/database.get_db` 未覆盖**：测试统一覆盖依赖，实际会话生命周期（close）未被自动化验证；建议在集成环境补一条直连测试。

## 6. 结论与建议

1. 后端核心业务（预约、签到/签退、违约、黑名单、场地关闭、登录限流、定时任务）语句覆盖已达 **97.0%**、分支覆盖 **91.3%**，综合 **96%**，关键模块均超过 90%。
2. 白盒补充用例全部通过，未发现业务回归；既有 137 条回归与 37 条 QA 用例保持通过。
3. 建议将覆盖率纳入 CI：后端语句 **≥90%**、分支 **≥85%**，前端语句 **≥90%**、分支 **≥80%**；当前均已满足。
4. `pytest-cov` 已安装（6.3.0），后续可直接用 `--cov-branch` 生成报告并接入流水线；建议把 `pytest-cov>=6,<7` 写入测试依赖。
5. 对本报告 §2.3 的竞态分支，建议在 MySQL 环境做故障注入（如唯一约束冲突、连接重试耗尽）专项验证。
