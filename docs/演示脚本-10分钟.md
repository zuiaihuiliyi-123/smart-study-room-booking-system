> 适用版本：`main` 分支当前实现（含 5 分钟预约粒度、场地关闭时间窗、登录锁定）。
> 演示数据脚本：`backend/scripts/seed_demo_data.py`；重置入口：仓库根目录 `reset-demo.bat`。

## 0. 演示前准备（提前 5 分钟）

### 0.1 启动

1. 双击仓库根目录 `start.bat`，等待出现：
   - `Backend is up.`
   - `Frontend is up.`
2. 浏览器打开 <http://127.0.0.1:5173>。

### 0.2 重置演示数据（每次演示前执行）

双击根目录 `reset-demo.bat`，或在 `backend/` 目录执行：

```bash
python -m scripts.seed_demo_data --reset
```

成功时应看到类似输出：

```text

演示数据已就绪：预约 15 条、违约 5 条、投诉 4 条、评价 4 条、消息 19 条、场地关闭 1 条。
```

> **重要**：演示数据是相对“当前时间”生成的。请**在演示开始前 5～10 分钟内重置**；
> 若距离重置超过约 20 分钟，“待签到”的预约会错过签到窗口，需重新执行 `--reset`。
>
> `--reset` 只清理演示账号（`student`、`demo_*`）的业务数据和原因以「【演示】」开头的
> 场地关闭记录；不会删除其他用户数据、审计日志或表结构。审计日志按 NFR-009 只追加。

## 3. 分步脚本

### 3.1 开场（约 30 秒）

讲稿要点：

> 这是智慧自习室预约与管理系统，前后端分离：Vue 3 + TypeScript + Element Plus，
> FastAPI + SQLAlchemy + MySQL。核心业务是“选座—预约—签到—签退—违约—黑名单”，
> 管理端负责资源、预约、违约、投诉、看板和审计。预约粒度是 **5 分钟**，
> 同一座位同一时段最多一条有效预约，由数据库唯一约束和事务共同保证。

### 3.2 注册 / 登录（约 60 秒）

1. 打开 <http://127.0.0.1:5173/register>。
2. 填写：
   - 姓名：`演示同学`
   - 学号 / 工号：`demo_<当前时分>`（例如 `demo_1420`，避免与已有账号重复）
   - 密码 / 确认密码：`demo123456`
3. 点击「注册并登录」。

预期：

- 提示「注册成功，已为你登录」，进入学生端首页。
- 说明：自助注册只开放「学生用户」角色；管理员账号由信息中心分配；注册接口有限流。

4. 退出登录，改用 `student / student123` 登录（后续演示依赖预置数据）。

讲稿要点：

> 密码使用不可逆哈希存储；登录失败按“学号 + IP”计数，连续失败会临时锁定；
> 管理员与学生共用登录入口，但路由守卫按角色隔离。

### 3.3 选座与预约（约 90 秒）

1. 左侧菜单「预约座位」。
2. 在顶部筛选条：
   - 日期选择「明天」；
   - 自习室选择「第一自习室」；
   - 开始时间选 `16:00`，结束时间选 `17:00`（下拉框按 **5 分钟**步进）。
3. 在座位图中点击一个可用座位（如 `B-03`），底部出现已选信息。
4. 点击「确认预约」。

预期：

- 提示预约成功，「我的预约」新增一条“待使用”。
- 若选择已被占用的座位，底部会显示冲突原因，且「确认预约」不可用；服务端仍会二次校验。
- 讲解：预约写入 `reservations` 与 `reservation_slots`（每 5 分钟一行），
  `(seat_id, slot_start)` 与 `(user_id, slot_start)` 唯一约束保证并发下不重复占用；
  幂等键保证重复提交返回同一结果。

### 3.4 取消预约（约 40 秒）

1. 菜单「我的预约」。
2. 找到明天 `09:00–11:00` 的预约，点击「取消」。
3. 确认取消。

预期：

- 状态变为「已取消」，时段重新开放，收到“预约已取消”站内消息。
- 讲解：距开始不足 30 分钟时「取消」按钮会禁用并提示；管理员强制取消属于另一条路径。

### 3.5 签到 / 签退（约 60 秒）

1. 回到「我的预约」。
2. 找到**即将开始**的那条“待使用”预约（脚本生成时约 10 分钟后开始，签到窗口已打开）。
3. 点击「签到」。

预期：

- 状态变为「使用中」，签到时间被记录；重复签到会被拒绝。
- 讲解：签到窗口为开始前 15 分钟至开始后 15 分钟；超时未签到由定时任务判违约。

4. 点击「签退」。

预期：

- 状态变为「已完成」，该时段对他人重新可预约。
- 可点击「评价」提交 1～5 分（同一预约只能评价一次）。

### 3.6 违约与黑名单（约 50 秒）

1. 新开无痕窗口，用 `demo_wang / demo1234` 登录。
2. 打开「我的违约」。

预期：

- 显示 3 条自动违约记录（超时未签到）。
- 账户状态为「受限」，首页可能出现限制提示。

3. 尝试「预约座位」并提交。

预期：

- 被拒绝，提示“账户当前为「受限」，暂不能创建预约”，并显示预计解除时间。

4. 切回管理端窗口，打开「黑名单管理」。

预期：

- 王浩：来源「自动」，原因“累计有效违约达到 3 次”，有期限；
- 孙悦：来源「手动」，到期后仍需管理员解除（BR-010）。
- 讲解：自动限制 7 天后自动解除；手动限制不自动解除；同一用户最多一条有效限制。

### 3.7 场地关闭：影响清单 + 二次确认（约 110 秒）

> 这是需求里最强调“先展示影响、再确认”的流程。

1. 管理端「自习室管理」→ 第一自习室 → 点击「临时关闭」。
2. 关闭窗口填写：
   - 开始：明天 `16:00`
   - 结束：明天 `17:00`
   - 关闭原因：`【演示】设备检修`（前缀用于重置时识别）
3. 点击「查询受影响预约」。

预期：

- 列出该时段内的有效预约（应包含 3.3 中刚创建的 `B-03` 预约，可能还有明天的其他预约）。
- 清单只读展示，预约状态不变。

4. 保持默认“保留预约”，点击「确认执行关闭」，在二次确认框中确认。

预期：

- 关闭成功：显示“保留 N 条、取消 0 条”。
- 学生端收到“所选座位临时关闭”消息，预约仍为“待使用”。
- 讲解：确认前不会自动取消；只有管理员显式勾选“一并取消”才会批量取消且不计违约；
  关闭只在时间窗内生效，窗口结束自动恢复，座位资源状态不变。

5. 可选：切回 `student`，打开「站内消息」查看上述通知。

### 3.8 手动违约 + 投诉处理（约 50 秒）

**手动违约**

1. 管理端「预约管理」→ 状态筛选「使用中」。
2. 找到 `demo_zhao` 的预约，点击「详情」。
3. 在“登记原因”中填写：`演示：长时间离座未签退`。
4. 点击「手动违约登记（将累加违约次数）」，在确认框中确认。

预期：

- 预约状态变为「已违约」，该用户违约次数 +1，生成违约记录与站内消息，写入审计日志。

**投诉处理**

1. 管理端「投诉处理」→ 默认“待处理”队列。
2. 打开 `student` 的投诉（A-04 台灯不亮）。
3. 选择「受理」，处理说明填写：`已联系物业更换台灯`，提交。
4. 再次打开该投诉，选择「录入处理结果」，说明填写：`已更换台灯并回访`，提交。

预期：

- 状态依次变为「处理中」→「已处理」；学生收到投诉反馈消息；审计日志新增记录。
- 讲解：「已关闭」只能由投诉人确认或系统超时触发，管理端不提供直接关闭入口。

### 3.9 看板与审计（约 60 秒）

1. 管理端「数据看板」。

预期：

- 顶部显示“数据截至时间”“自动刷新次数”“下次刷新倒计时”。
- 等待约 10 秒，可看到刷新次数增加、截至时间更新。
- 图表：自习室座位使用时段、每日预约/违约趋势、违约 Top N。

讲稿要点：

> 10 秒是**数据读取周期**，不是违约任务执行周期；页面显示截至时间，避免把旧数据当实时值。

2. 管理端「审计日志」。

预期：

- 可看到 `ROOM_TEMP_CLOSE`（场地关闭）、`MANUAL_VIOLATION`（手动违约）、
  `COMPLAINT_HANDLE`（投诉处理）、`BLACKLIST_AUTO_RESTRICT`（自动限制）等记录。
- 按操作类型/操作人/日期筛选；页面只读，不提供修改、删除或导出（FR-033 已排除）。

### 3.10 收尾（约 30 秒）

讲稿要点：

> 核心业务闭环已经打通，服务端完成并发、幂等、权限与审计校验；
> 自动化测试包括后端 261 条通过（3 条跳过）、前端 65 条单元测试和 6 条 Playwright 主流程；
> 一键启动脚本会完成建库、迁移、演示数据和前后端启动。
> 下次演示前运行 `reset-demo.bat` 即可恢复初始数据。

## 4. 常见追问与回答

| 追问 | 回答要点 |
|---|---|
| 为什么粒度是 5 分钟？ | 2026-11-07 产品确认 BR-001 由 30 分钟调整为 5 分钟；看板占用率仍按 30 分钟统计块展示。 |
| 两个人同时抢同一座位怎么办？ | 事务内对座位/用户行加锁，`reservation_slots` 的 `(seat_id, slot_start)` 唯一约束是最终兜底；冲突方收到 C3/C4 具体原因。 |
| 重复点击“确认预约”会不会生成两条？ | 前端一次请求一个幂等键；同一用户同一幂等键重复提交返回同一条预约；不同键但时段相同会被冲突校验拒绝。 |
| 自动违约和手动违约有什么区别？ | 自动：超时未签到，由定时任务幂等登记；手动：管理员对“使用中”预约登记，必须填原因并记录操作者。 |
| 黑名单什么时候解除？ | 自动限制 7 天到期自动解除；手动限制到期后仍需管理员解除（BR-010）。 |
| 为什么没有短信/邮件/导出？ | 本期范围仅站内消息；FR-024 申诉、FR-033 导出等已由需求裁定排除。 |
| 审计日志能不能改？ | 只追加、不修改不删除；管理端只读查询。 |

## 5. 故障兜底

| 现象 | 处理 |
|---|---|
| 签到按钮不可用 / 提示超出窗口 | 演示数据已过期：运行 `reset-demo.bat` 后重新登录。 |
| 预约提示时段冲突 | 上一次演示留下了预约：运行 `reset-demo.bat`。 |
| 登录提示账户受限 | 用了 `demo_wang` 或 `demo_sun`；改用 `student`，或重置后重试。 |
| 端口被占用 | 运行根目录 `stop.bat`，再运行 `start.bat`。 |
| 管理端看不到“临时关闭” | 只有「自习室管理员」有业务页权限；确认使用 `admin` 登录。 |
| 网络/服务异常 | 使用提前录制的演示视频或截图；先保证不中断讲解。 |
