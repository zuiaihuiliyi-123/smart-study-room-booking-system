# 智慧自习室预约与管理系统

面向高校自习空间的座位预约、使用管理与数据分析平台。

> **当前阶段：需求分析 + 开发骨架。** 本仓库包含需求分析阶段的文档与图模型，以及基于 FastAPI + Vue 3 的前后端项目骨架；业务逻辑尚未实现。

## 仓库结构

```
.
├── README.md
```

## 重要约定

**候选状态的规则未获确认。** 需求规格说明书与图模型中标注为【AI 候选】或【分析推导】的内容，确认状态均为「待确认」，代表尚未经业务方或任课教师确认，不应视为已生效的业务规则。详见说明书第 11 节及附录 A。A 报告中的「已确认」均指 **2026-10-29 团队内部复核**，不代替业务方与教师确认。

**A 报告中的「未开展」是真实状态。** 业务方访谈、教学模拟确认与教师确认**均未开展**；A.5 场景走查、A.6 原型走查与 A.8 成员贡献仅为**团队内部方式完成**。A.7 的 V-01～V-15 处理结论已按团队内部复核登记，但**不得**把「已修改」「已确认（团队内部复核）」理解为业务验证通过，也不得把设计意图表述为已验证。`提交作业/` 目录为课程提交版本，与 `docs/` 存在差异时**以 `提交作业/` 为准**（见 `提交作业/提交说明-作业检查清单.md`）。

## 参与贡献

1. 从 `main` 分支切出特性分支：`git checkout -b docs/your-topic`
2. 提交时使用清晰的提交信息，说明改动的文档与章节。
3. 发起 Pull Request，由至少一名小组成员复核后合并。

**注意：** 附件与证据材料在提交前应移除密码、令牌及与核验无关的个人敏感信息。
